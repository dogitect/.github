# Contributing

Thanks for taking the time to look at this. Please read this short policy
before opening an issue or pull request.

## TL;DR

These are **personal, solo-maintained open-source projects**, released purely
out of passion. They generally **do not accept external contributions**. If
you want to change something, the recommended path is to **fork and build your
own version** — the MIT license fully supports that.

## Pull Requests

External pull requests will typically be closed without merging, even if the
change looks reasonable. This is not a judgment on the quality of the work —
it's a deliberate choice to keep the maintenance burden sustainable for a
single developer.

The only exceptions are changes that have been **explicitly coordinated with
the maintainer in advance** (for example, in a related issue or discussion
where the maintainer asked for a PR).

## Issues & Discussions

You are welcome to open issues to:

- Report bugs you've encountered
- Ask questions about how something works
- Share ideas or suggestions

Responses are best-effort and may take a while. Please don't take silence
personally — it usually just means I haven't had time.

## Forking is Encouraged

All public projects are released under the **MIT license**. If you'd like to:

- Fix a bug for your own use
- Add a feature you need
- Adapt the project for a different use case
- Build a commercial product on top of it

…just fork it and go. **You don't need to ask for permission.** The only
requirement is keeping the copyright and license notice as required by MIT.

## Code of Conduct

All interactions in issues and discussions are subject to the
[Code of Conduct](CODE_OF_CONDUCT.md). Please be respectful.
